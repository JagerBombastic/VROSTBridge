## 1.0.0.15 summary

1.0.0.15 answers November's sessions and a review of every 1.0.0.14 report: SteamVR's dashboard volume reaches the captured game audio, SteamVR's safe mode is caught before it strands a session and can be undone from the headset PC, the headset's USB and blinded controllers are explained, the bitrate starts where it settled, game audio stays in time through stalls, a lower power limit is pointed out, and the rendering PC's stalls are recorded. Every package carries version 1.0.0.15. See [RELEASE_1.0.0.15.md](RELEASE_1.0.0.15.md) and [DEVELOPMENT_CHECKPOINT.md](DEVELOPMENT_CHECKPOINT.md#s-novembers-sessions-and-the-10014-reports-10015).
- **Rebuilt, and why:** the host's driver for patch 0023 (the dashboard volume), the first new driver since 1.0.0.9; the clients' transport for patch 0022 (the audio's aim through stalls); both clients' native programs for the version label only, their code being 1.0.0.14's; and the companion, frozen again. The shaders, Vulkan layer, lease helper, camera helper, FFmpeg, embedded Python and the host's helpers are 1.0.0.14's, byte for byte, except Windows' FFmpeg DLLs: built again from the same source, they differ from the earlier ones only in the time stamp the old build left in their headers. The build leaves none now, so it reproduces.
- **No build machine in the programs:** the driver and both transports are built with the build folders mapped out (`/src`, `/cargo`, `/rustup`), and each build refuses a file that still names one. The Linux transport's build gained that mapping and check in this release: its first build here named the build machine's Cargo folder.
- **Tests:** 1,624 Python tests, 34 of them new in `tests/test_vrostbridge_1015.py`; 4 skipped here (three need PowerShell or the VB-CABLE package; the launchers' build ran on its own with the cross toolchain and passed). The page checks in Node, the Rust tests of the two changed patches, and native CTest: 30/30 on Linux and 29/29 for the Windows build under Wine with lavapipe.
- **Packages:** each payload's manifest verifies, and its documents, licences and notices are the repository's. Against 1.0.0.14, only the rebuilt or relabelled programs, the companion's changed Python files and page, the manifests and the documents differ, and in the frozen companion the system's zlib and liblzma, newer Ubuntu builds of the same versions. Each frozen module is the repository's source as Python 3.12 compiles it. The Bazzite companion's `--self-test` passed, and both Windows launchers' under Wine.
- **Scans:** the five packages and the source archives, opened up (archives, zlib streams and PDF text, also as UTF-16): no build-machine path and none of the maintainer's personal details or hardware names.
- **Not verified here:** everything new on hardware (the dashboard slider in the headset, safe mode and its fix, a USB dropout, blinded controllers, a hub too deep, the remembered bitrate, the audio through a real stall and the lower-power note), and everything of the Windows client on real Windows.
