## 1.0.0.14 summary

1.0.0.14 answers the first external testers (the latency good, the foveation invisible; notes missed in a rhythm game, fine detail softer than on a directly connected headset) and 1.0.0.13's first session, whose adapter counters placed the lost frames in the headset PC's socket buffer: the headset PC folds each controller's acceleration into the poses it sends, so the rendering PC's first-order prediction lands where a swinging hand will be; the rendering PC renders at the headset PC's recommended size (at most 1.5 × the stream) and scales down for the encoder; *Auto* codec is HEVC on every headset, 10-bit where the headset PC decodes it, with the Bazzite client reading the GPU's VA-API profiles; the automatic bitrate's ceiling is a third higher; on Bazzite a headset PC on its network by cable and Wi-Fi is offered two standard settings once, which keep the video on the cable with Wi-Fi connected, and a Wi-Fi pause that cuts the host off is undone at once; paired headset PCs start sessions on any Windows network type; the sharp region is predicted through the head's turn; and the host keeps its last session's statistics for a report made after a restart. Every package carries version 1.0.0.14. See [RELEASE_1.0.0.14.md](RELEASE_1.0.0.14.md) and [DEVELOPMENT_CHECKPOINT.md](DEVELOPMENT_CHECKPOINT.md#r-the-first-external-testers-and-10013s-first-session-10014).
- **Toolchain:** as 1.0.0.13, with libva for the Linux client's decoder-profile query. The driver, both transports and FFmpeg's DLLs are 1.0.0.9's builds: `patches/` and `client/transport/` are unchanged.
- **Patches:** 0001 to 0023, unchanged.
- **Host:** the driver folder, the embedded Python and the helpers are byte-identical to 1.0.0.13's; the launcher is rebuilt for the version; the companion (the render size, the last session's record), documents and artwork come from the source.
- **Bazzite client:** the native client is rebuilt (the acceleration folded into the sent poses, the gaze predicted through the head's turn, VA-API's decoder profiles, the new `TIMING` fields) and is the one the tests ran; the runtime probe is 1.0.0.13's code with the new version, byte-identical once the version label and the build ID are set aside; every other native file is 1.0.0.13's. The companion is frozen again, and each of its modules is the repository's source as the same Python compiles it.
- **Windows client:** the native client is rebuilt likewise (its tests passed under Wine) and the runtime probe is relabelled (the same size and, the version label aside, 10 bytes apart: the link time stamps and the file version); the rest of the native folder, the transport included, is 1.0.0.13's. The embedded Python is the host's, byte for byte; the launcher is rebuilt for the version.
- **Against 1.0.0.13:** besides the documents, notices and manifests, only the rebuilt native client, the companion's changed or added Python files and its page, the version-labelled programs and the files that name the version differ; every other file of the five packages is byte-identical. Each payload's manifest verifies, and its documents, licences and notices are the repository's, file for file.
