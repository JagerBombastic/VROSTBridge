## From the first session of 1.0.0.12 (1.0.0.13)

The session confirmed 1.0.0.12's bitrate fixes and add-on warning. What held the picture back was the headset PC's decoder (behind at 65 Mbit/s at Native) and packets lost in clumps on the wired link.

- **More parity on a wired link:** one parity piece per 5 video pieces instead of 10, so a run of lost pieces up to a fifth of a frame is rebuilt; Wi-Fi keeps 10. Older clients repair either.
- **Stop while SteamVR starts:** the rendering PC no longer waits out the 90 s start, and asks SteamVR to exit itself when ALVR cannot (before a headset has streamed).
- **Display modes, before a session:** an Index's Native (2016 × 2240) at 80, 90, 120 or 144 Hz, chosen from the last headset seen or, on Bazzite, the one plugged in, and set in SteamVR for the session. A Beyond offers no choice: its stream follows the mode it is in (2560 at 75 Hz, 1920 at 90 Hz), which Bigscreen's Beyond Utility sets on a Windows PC.
- **Reports:** the network adapters' drop counters on every PC (`adapter_counters`), the remembered GPU clock and its use (`session_tuning`), and in Game Mode where SteamVR's server came from and which display it reached (`steamvr_origin`).
