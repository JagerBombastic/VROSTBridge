## Current change records

- [1.0.0.13 release](RELEASE_1.0.0.13.md) (host, Bazzite client and Windows client), from 1.0.0.12's first session on hardware: the stream chosen before a session (the Index's 80 to 144 Hz, its rate set in SteamVR for the session; a Beyond's stream following the mode it is in), one parity packet per five video packets on a wired link, a stop while the rendering PC's SteamVR starts no longer waiting out the start, the network adapters' drop counters and the remembered GPU clock in the reports, and where Game Mode's SteamVR came from; the native programs are 1.0.0.12's with the new version label.
- [1.0.0.12 release](history/RELEASE_1.0.0.12.md) (host, Bazzite client and Windows client), from 1.0.0.11's first session on hardware: the automatic bitrate back to where the session started when the headset PC's GPU clock is held higher, seconds in which frames never arrived (the rendering PC sent nothing for a moment) no longer counted against it, the GPU clock the last session needed held from the start on Bazzite, and the host's add-on warning limited to add-ons registered from outside SteamVR; the native programs are 1.0.0.11's with the new version label.
- [1.0.0.11 release](history/RELEASE_1.0.0.11.md) (host, Bazzite client and Windows client), so a headset's full resolution fits lighter headset PCs: the one-pass frame shader's foveation inverse worked out once per frame for each eye, axis and region instead of per pixel, and each eye in its own workgroups (about a third less work per pixel by the driver's compiler statistics, the same picture; one shader for every GPU, its constants in a uniform buffer); the pixels the lenses never show skipped (SteamVR's visible-area mesh and lens-distortion outline, a 3 % margin, `VISIBLE_AREA`); each eye shown at 90 %, then 80 % of its size while the graphics hold the stream below refresh, and back when there is room (`launcher/output_scale.py`, `scale N`); the frame pass and the plane copy timed on the GPU (`frame_pass_gpu` and `plane_copy_gpu` on the client's TIMING lines; the pass also on the page and in the timeline); the Beyond's 2560 called Native. Version 1.0.0.11 for every package; the host's driver is 1.0.0.9's.
- [1.0.0.10 release](history/RELEASE_1.0.0.10.md) (host, Bazzite client and Windows client), from the 1.0.0.9 test: the system button forwarded as one clean press of at least 0.12 s, also read from SteamVR's own button event, and the other controls kept through a loss of input focus shorter than half a second (the headset PC's SteamVR takes focus while its system button is held); in Game Mode, SteamVR started without gamescope's display marker and with the headset display under a plain name, a compositor that cannot take it stopping Start at once with the reason, the display SteamVR's server was given and the display adapter's clients logged, and the last Game Mode start kept for the reports; a bitrate step for uneven arrival undone when frames arrive no more evenly at the lower bitrate, and seconds with too few frames not counted as uneven; three tries for a base station, on Bazzite with a fresh search before each retry and the signal strength of one not reached. The host's driver is 1.0.0.9's.
- [1.0.0.9 release](history/RELEASE_1.0.0.9.md) (host, Bazzite client and Windows client), from the 1.0.0.8 test: game audio played on the headset PC by a player of VROSTBridge's own (the stream's own rate where the device allows, a windowed-sinc converter where it does not, a steady buffer held by a speed correction of at most 0.5 %, lost packets bridged, a fade and a longer buffer when it runs dry; patch 0022) and captured on the rendering PC from Windows' loopback stream directly (silent packets as silence, a silent render stream through quiet moments, *Pro Audio* scheduling, surround folded by speaker position; patch 0023); parity for video frames and game audio so the headset PC rebuilds lost pieces (patch 0021, `fec_video_group` 10, `fec_audio_group` 1); Baballonia at a quarter of the normal CPU weight on Bazzite; a second try for a base station that did not answer, and on Bazzite one station at a time; the host keeps the 3 newest client reports. New host driver.
- [1.0.0.8 release](history/RELEASE_1.0.0.8.md) (host, Bazzite client and Windows client), from the 1.0.0.7 test: automatic bitrate held to what the picture needs (a ceiling from codec, encoded size and frame rate), stepped down when decoding falls behind or frames go missing and back up as the stream runs clean, and changed on the rendering PC while the stream runs (`bitrate-control`); video paced at 70 % of the network test's loss-free rate; *Use recommended settings*; *Balance performance during sessions* on Bazzite (the power limit and GPU clock through steamos-manager, only while streaming, set back at Stop); SteamVR 2.0 base stations on at Start and off when the client closes, over the headset PC's Bluetooth; *Keep my gaze centred* per calibration and *Use previous calibration*. The host's driver is unchanged.
- [1.0.0.7 release](history/RELEASE_1.0.0.7.md) (host, Bazzite client and Windows client): the Windows client, so that the headset PC can run Windows 10 or 11 (64-bit) as well as Bazzite, with the same native client, page and stream, decoding through Direct3D 11 video decoding (D3D11VA) with FFmpeg 6.1.4 and a copy into the frame shader, eye-tracked foveation with Baballonia's Windows installer on a Beyond 2e, a tray icon with *Start session* and *Stop session*, start at sign-in, firewall rules in one step (private networks and the local subnet only), Wi-Fi media streaming mode and no background scans during sessions, *Best performance* while streaming, and plain messages when SteamVR is not set up yet; a per-user installer without administrator rights (`VROSTBridge-Client-Setup-1.0.0.7.exe`) or a portable ZIP. Game Mode stays with Bazzite. Not yet run on Windows hardware. Both clients: a variant of the one-pass frame shader for graphics drivers with only the minimum push-constant space. The host's driver is unchanged and its companion shares the Windows client's network code; every package carries version 1.0.0.7.
- [1.0.0.6 release](history/RELEASE_1.0.0.6.md) (host and client), from the 1.0.0.5 test: how far the gaze reached each way, measured per session and shown (*Gaze reach*, *Measure again*, Game Mode, reports) with calibration steps that turn the head far enough (Baballonia reports only as far as its calibration went, and at most 45°), the host's per-window gaze and region extremes and its 10-bit conversion tried as plain SDR first with each check logged (driver patch 0020, `VROST_COLOR_PROBE`), a network test that judges lateness by what the network added (`network_spread_p95_ms`) and tests again once after an old result, and the controllers' prediction measured on the headset PC (`controller_prediction`), version 1.0.0.6.
- [1.0.0.5 release](history/RELEASE_1.0.0.5.md) (host and client), from the 1.0.0.4 test: exact 10-bit colour on AMD graphics (the host converts and labels it itself and checks it with a test picture at every stream start, or streams 8-bit; driver patch 0018, `VROST_COLOR`), frames the host could not send without a head position counted (`VROST_NO_HEAD_POSE`) and *Headset not tracked* on the client, eye cameras passed on as sent at their fastest rate with lost USB data costing one frame (`STATS` lines in reports), Baballonia's filter following within two camera frames, a comfort zone that keeps the sharp region still for small eye movements (driver patch 0019, `gaze_comfort`), a stream larger than SteamVR's size shown at that size, and a network test that measures the network rather than the busy companion and is repeated when it finds no clean rate, version 1.0.0.5.
- [1.0.0.4 release](history/RELEASE_1.0.0.4.md) (host and client), from the 1.0.0.3 test: the sharp region kept where you last looked through pauses in the gaze (driver patch 0017, `gaze_hold_ms`), a processor held below its own minimum clock by the shared power limit noticed and explained (one-click automatic GPU clock where steamos-manager runs), wired video pacing kept under the path's measured loss-free rate, the last frame held re-aimed for up to a second before the grey recovery view, Game Mode controls that change settings with left and right and repeat when held, and a session timeline in reports, version 1.0.0.4.
- [1.0.0.3 release](history/RELEASE_1.0.0.3.md) (host and client), from the 1.0.0.2 test: Game Mode's headset display reservation recognised (Bazzite's gamescope has a file capability), the host's SteamVR closes after SteamVR starts another server process, the reduced area of the foveated stream filtered on the host (driver patch 0016) and enlarged smoothly on the headset PC, eye tracking up to about 66 samples a second with a quicker Baballonia filter, a clearer eye-tracking view, Baballonia kept across updates and uninstalls, version 1.0.0.3.
- [1.0.0.2 release](history/RELEASE_1.0.0.2.md) (host and client; only the client changes): Baballonia's eye calibration no longer crashes as a SteamVR overlay on Bazzite. A Vulkan layer of VROSTBridge's own, for that program only, switches on the Vulkan extensions SteamVR uses to take the overlay's picture, which the program does not enable and Mesa does not hand over without them. Version 1.0.0.2 on both programs.
- [1.0.0.1 release](history/RELEASE_1.0.0.1.md) (host and client), the first release under the VROSTBridge name: *VR Rendering OutSide The Box – Bridge* under the name, one name for every program, folder, setting, registration, protocol name and driver file (a fresh installation; remove earlier test builds first), version 1.0.0.1.
- [1.0.0 release](history/RELEASE_1.0.0.md) (host and client), the first release build: the logo everywhere; and from the first RC4.5 test (as the unreleased RC4.6): Baballonia's calibration runs as a SteamVR overlay over the stream, so the session keeps running (its OpenXR way made SteamVR end the stream); Baballonia starts minimised with *Show Baballonia*; one page tab when the page is opened again; the card says when a calibration would show on the screen and names the *Eye* calibration; the MIT licence, `NOTICE`, a full third-party list in both packages, and the camera helper's own MJPEG server, ready for public release.
- [RC4.5 release](history/RELEASE_1.0.0-rc4.5.md): eye tracking set up and run by VROSTBridge: one *Eye tracking* switch; *Set up eye tracking* downloads Baballonia 1.1.1.0rc6 from Project Babble (pinned SHA-256, licence shown and accepted); each session starts and stops the Beyond 2e eye cameras, Baballonia and the gaze relay; calibrate once in Desktop Mode; the host turns eye tracking on for the session (`session-gaze`); notes that name what is missing; recovery when the cameras or Baballonia end.
- [RC4.4 release](history/RELEASE_1.0.0-rc4.4.md): from the RC4.3 test: the graphics warning names a held-back GPU (stuck at 800 of 2700 MHz: raise the TDP limit, GPU clock on automatic) and its clock is shown live, one automatic session restart when SteamVR's compositor on the headset PC crashes (native client ignores SIGPIPE), a lighter fused frame pass (5-tap Catmull-Rom, analytic foveation density), in-headset cards at twice the pixels per degree, eye-tracked settings shown whenever Eye-tracked is chosen with why the region does not follow the eyes, and the Game Mode display adapter kept for the whole session.
- [RC4.3 release](history/RELEASE_1.0.0-rc4.3.md): one-step headset microphone on the host (VB-CABLE by VB-Audio, downloaded and opened on request), Game Mode that recognises the Beyond 2e by its head-mounted display markers and says why when the display is not reserved, every setting on the Game Mode screen, B no longer closes it, headset-PC graphics limit with one-tap smaller size (Auto starts the Beyond at 2016), one fused GPU pass per shown frame (sharper, lighter) with adjustable sharpening, eye-tracked foveation tuning and a live eye view on both pages and in Game Mode, two stream-recovery fixes, Wi-Fi 7 multi-link bands; host companion update over the RC4.1 driver; physical results pending.
- [RC4.2 release](history/RELEASE_1.0.0-rc4.2.md): even pose timing locked to the display, frame re-aim with an in-headset alignment check, Wi-Fi kept on one access point during sessions (no five-minute stalls), Wi-Fi/Ethernet detection, SteamVR-style in-headset cards, Game Mode that keeps the handheld's screen on with a one-button Steam entry and artwork, versioned reports with client-to-host upload, reorganised pages; host companion update over the RC4.1 driver; physical results pending.
- [RC4.1 release](history/RELEASE_1.0.0-rc4.1.md): fixes from the first RC4 test: motion predicted once (patch 0014), AMD encoder backlog (patch 0013), reconnection after a Wi-Fi dropout and automatic stream recovery, second Wi-Fi adapter paused, host driver log in reports, no host SteamVR restart for the headset (patch 0015), faster compositor-crash recovery, measured Wi-Fi pacing, microphone/reprojection/Wake-on-LAN checks, live foveation status, wider late-frame catch; physical results pending.
- [RC4 release](history/RELEASE_1.0.0-rc4.md): foveated encoding (fixed and Beyond 2e eye-tracked), 10-bit and AV1, network test with automatic bitrate, video pacing, gradual loss recovery, in-headset status, keep-awake, Wake-on-LAN, sleep after session, quick resume, headset audio, reprojection check, per-headset settings, FFmpeg-free Windows host; physical results pending.
