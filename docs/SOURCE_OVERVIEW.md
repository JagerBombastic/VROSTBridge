# Source overview

For VROSTBridge 1.0.0.13, host, Bazzite client and Windows client, 2026-10-15. The friendly introduction is the [README](../README.md); this page is for people reading or changing the code.

## Layout

All three programs share one source tree.

| Folder | What is in it |
| --- | --- |
| `client/` | The native client, one source for Bazzite and (from 1.0.0.7) Windows: decoding (FFmpeg with VA-API on Bazzite, D3D11VA on Windows), Vulkan presentation, the foveated-encoding inverse, frame re-aim, tracking and input through the local SteamVR, the in-headset cards (`client/ui/`), and the Rust adapter to ALVR's client core (`client/transport/`, built as `libvrostbridge_transport.so` and `vrostbridge_transport.dll`). `client/platform/linux/` holds the main loop, Vulkan, the decoder, the shaders and the runtime probe, which build both clients (with Windows sections), and the Bazzite-only lease helper and Vulkan layer for Baballonia's calibration overlay (`openvr_texture_layer.c`). `client/platform/windows/` (1.0.0.7) holds the Windows-only parts: D3D11VA decoding on SteamVR's GPU (`d3d11_video.*`), the copy of each decoded picture into Vulkan (`vulkan_upload.cpp`), the command pipe, console events and scheduling (`process.hpp`), DLL loading (`dynamic_library.hpp`), and the programs' version resource and manifest (`version.rc.in`, `vrostbridge.manifest`). In `client/device/`, `planar_upload.hpp` and `decoded_planes.hpp` (1.0.0.7) are the plane upload that D3D11VA and CPU decoding share, and `gaze.hpp` takes the gaze from a Unix socket or, on Windows, loopback UDP. From 1.0.0.11 `visible_area.hpp` works out which pixels of each eye the frame pass computes (inside SteamVR's visible-area mesh and its lens distortion's outline), and `conversion.hpp` holds the pass's per-frame constants (`FusedFrame`, `fusedAxis`) and the shown size's scaling. `client/main.cpp`, `renderer.*`, `runtime.*`, `common.hpp` and `gaze_probe.hpp` are the sources of the early Windows diagnostic, which is no longer built; its runtime assets (`client/assets/`: the SteamVR action manifest and bindings, the headset cards' logo) |
| `core/` | Small shared C++ contracts (versions, headset EDID rules) |
| `host/` | Windows orchestration and helpers: driver registration, the VR and audio probes, headset microphone set-up, the vendored `websockets` |
| `launcher/` | The companions (Python): the desktop pages (`desktop.html`), the Game Mode screen (`game_ui.py`), sessions, network, Wi-Fi, eye tracking (`eye_tracking.py`, `baballonia.py`), fonts and the runtime artwork (`launcher/brand/`). From 1.0.0.7 also the Windows client's parts: `windows_network.py` (IP Helper and Native Wifi), `windows_power.py` (power mode, keep-awake, processor and GPU readings, sound device names), `Client-Firewall.ps1` (its firewall rules), the tray (`windows_tray.py`) and sign-in start (`windows_startup.py`) for both Windows programs, and Windows branches in, among others, `app.py`, `client_runtime.py`, `client_network.py`, `wifi_*.py`, `network_test.py`, `session_power.py`, `power_balance.py`, `graphics_limit.py`, `performance_monitor.py`, `headset_audio.py`, `baballonia.py`, `eye_tracking.py`, `gaze_provider.py` and `install_maintenance.py`. From 1.0.0.8: `stream_budget.py` (the picture's bitrate ceiling and the bitrate governor), `session_tuning.py` (the Bazzite performance balance through steamos-manager), `base_stations.py` and `BaseStations.ps1` (SteamVR 2.0 base stations over BlueZ and Windows' Bluetooth API), and in `gaze_provider.py` the gaze centring (`GazeCentre`). From 1.0.0.11: `output_scale.py` (each eye shown a step smaller while the headset PC's graphics hold the stream below refresh, and back at full size when there is room) |
| `brand/` | The VROSTBridge name and logo as the maintainer supplied them, the vectors rebuilt from them, exports, the small-icon refinement and its notes |
| `patches/` | The twenty-three ordered patches to the pinned ALVR revision (consent, networking, controllers, capture/AMF, the native protocol, chaperone, the frame-timing lock, stream statistics, pacing, foveated encoding, AMF intra refresh, optical-centre foveation, AMF output drain, the prediction switch, startup display configuration, the filtered reduced area (1.0.0.3), the gaze hold (1.0.0.4), exact colour and frames without a head pose counted, and the gaze comfort zone (1.0.0.5), the colour converter tried as plain SDR first and how far the gaze and the region reached (1.0.0.6), and for 1.0.0.9 packet repair for video and game audio (0021), the clients' game-audio player (0022) and the host's game-audio capture (0023)). `scripts/host_module_tests.py` runs the tests of the driver's own Rust modules on Linux; the patched crates' own tests run with Cargo ([BUILDING.md](BUILDING.md)) |
| `third_party/` | OpenVR headers and loaders (`libopenvr_api.so`, `openvr_api.dll`), the FFmpeg n6.1.4 source used for both clients with the build notes of each (`BUILD.txt`, and `BUILD-Windows.txt` from 1.0.0.7), go-bsb-cams (the eye-camera helper, GPL-2.0, with VROSTBridge's changes), stb, Wayland provenance |
| `packaging/` | Installer assembly: the host's NSIS script and the launcher for both Windows programs (`windows-launcher.c`, `build_windows_launcher.py`), the Bazzite installer, `build_distributions.py`, `repack_host_payload.py`, and from 1.0.0.7 the Windows client's installer (`windows-client-installer.nsi`) and package builder (`build_windows_client.py`) |
| `scripts/` | The scripts that build or start each part from the source (`Build-Client-Linux.sh`, `Build-Eye-Camera-Linux.sh`, `Build-Host-Windows.cmd`, `Build-Windows.cmd`, `Start-Client.sh`, `Start-Host.cmd`, and two desktop shortcuts), the CMake toolchains for cross-building (`cross/`, with the Windows client's `windows-clang-cl.cmake` from 1.0.0.7), builds (Linux client, FFmpeg, Windows host cross-build, and from 1.0.0.7 the Windows client's cross-builds: `Build-FFmpeg-Windows.sh`, `Build-Client-Transport-Windows.py`, `Build-Client-Windows.py`), the source archives (the whole source, and from 1.0.0.11 the source split by part: `package_component_sources.py`), fonts and artwork, the two PDFs |
| `tests/` | Python, page and native regression tests. From 1.0.0.7 the Windows client's Python parts are tested on Linux with stand-ins for Windows (`test_windows_network.py`, `test_windows_power.py`, `test_windows_runtime.py`, `test_windows_eye_tracking.py`, `test_windows_ui.py`, `test_windows_packaging.py`, and `test_vrostbridge_1007.py` for the release as a whole; from 1.0.0.8 `test_vrostbridge_1008.py`, with stand-ins for ALVR's settings interface, steamos-manager and BlueZ, from 1.0.0.9 `test_vrostbridge_1009.py`, from 1.0.0.10 `test_vrostbridge_1010.py` and from 1.0.0.11 `test_vrostbridge_1011.py`, with `test_public_release.py` for the first public release: the documentation's links, the licence page and the source split by part), and there are new C++ tests: `planar_upload_tests.cpp` (the plane upload and the frame pass reading it) and `software_decode_tests.cpp` (CPU decoding, with its small H.264 files in `tests/fixtures/`) in both client builds, `gaze_receiver_tests.cpp` (gaze over loopback UDP and the Unix socket) and `visible_area_tests.cpp` (1.0.0.11, the pixels the frame pass computes) in every build, `video_pass_tests.cpp` (1.0.0.11, the client's own frame path against a stand-in SteamVR, `openvr_stand_in.hpp`, which `make_openvr_stand_in.py` writes from the OpenVR headers) in both client builds, and on Windows `windows_process_tests.cpp` (the command pipe, output lines and console events) |
| `licenses/` | Third-party licence texts, including every Rust crate's (`licenses/rust/INDEX.json`) |
| `docs/` | The documentation ([its home](README.md)) and the source's start page (`START_HERE.html`): guides, the technical reference and specification (each also as a PDF), the current release notes, build records in `evidence/`, the screenshot in `images/`, and the project's earlier records in `history/` |
| `.github/` | The checks workflow, the issue forms and the pull request template, with `CONTRIBUTING.md` (how to help) and `SECURITY.md` (how to report a vulnerability privately) |

`scripts/fetch_upstream.py` obtains the exact ALVR revision (`f5023f8e78fa14ea57fb1038548d7820289a8524`); the upstream checkout is not part of this repository, so native builds need internet access and the platform toolchains ([BUILDING.md](BUILDING.md)). Release packages are assembled as in [packaging/README.md](../packaging/README.md). `Build-Windows.cmd` builds and runs the contract tests on Windows with Visual Studio's CMake. The early Windows diagnostic (`VROSTBridge.exe`) is no longer built: its CMake target is gone, though its sources remain in `client/` and `scripts/package_windows_diagnostic.py` still refers to it. It was never the rendering host or the Windows headset client.

## Where things stand

- **Confirmed on the author's hardware:** Valve Index streaming, tracking and game audio; Bigscreen Beyond 2e streaming with good tracking and picture; the Beyond 2e eye cameras in Baballonia; Baballonia's calibration over the stream and the eye-tracked foveated stream in Desktop Mode (1.0.0.2 test); tracking that feels good from moment to moment (1.0.0.3 test); true blacks on the Beyond's OLED panels with 10-bit colour off, and the High size (now *Native*) looking and tracking reasonably well (1.0.0.4 test); motion and picture much steadier with 1.0.0.8's bitrate control, with a few short stutters left (1.0.0.8 test).
- **Built and tested in software, waiting for headset time:** 1.0.0.13 (the stream chosen before a session, with an Index's rate set in SteamVR and a Beyond's stream following its mode; more parity on a wired link, the stop while SteamVR starts, the adapters' drop counters, the record of where Game Mode's SteamVR came from), 1.0.0.12's GPU clock held from the start (its bitrate changes and add-on warning worked in its first session), 1.0.0.11's lens area on other headsets and each eye shown a step smaller to keep the frame rate (its frame pass and GPU time ran in its first session), 1.0.0.10 (the system button as one clean press, the other controls kept through a short loss of focus, Game Mode's SteamVR environment and its checks, the bitrate's arrival check, the base stations' searches between tries), 1.0.0.9's packet repair at High and base stations off at closing (its game audio, packet repair on Wi-Fi and Baballonia's CPU weight ran in the 1.0.0.9 test), 1.0.0.8's performance balance and gaze centring, 1.0.0.7's Windows client (built and tested on Linux and under Wine only: it has not run on Windows hardware), 1.0.0.6 (the gaze reach, the plain SDR colour attempt, the network test's lateness rule, the controller prediction check), 1.0.0.5 on real Windows and Bazzite installations (exact 10-bit colour, the eye cameras passed on at their fastest rate, the comfort zone, *Headset not tracked*, Ultra shown at SteamVR's size, the network test repeated when it finds no clean rate), 1.0.0.4's sharp region held through pauses in the gaze, processor warning, pacing, one-second frame hold and Game Mode controls, 1.0.0.3's Game Mode past the display reservation and filtered reduced area, Baballonia's calibration as an overlay during a session (1.0.0), eye-tracked foveation, Game Mode with the Beyond 2e, the RC4.x network, power and recovery features. Each release's notes end with what to test.
- **Not supplied:** decoding on the Windows client without the copy through system memory, eye tracking for games through OpenXR on the host, foveated rendering in games.

From 1.0.0.1 on, newer clients work with older hosts and turn on newer features only when a host advertises them. Version labels are independent of the protocol (`vrostbridge-session-2`); matching version strings are not required, though every package of a release carries the same version and is meant to be installed together.

## Release history

Each release has notes, with what changed and how to test it: the current one in `docs/RELEASE_1.0.0.13.md`, earlier ones in `docs/history/RELEASE_*.md`. In short: 1.0.0.13 the follow-ups from 1.0.0.12's first session (the stream size chosen before a session from the headset's modes, the Index's refresh rate set for the session, more parity on a wired link, a quick stop while SteamVR starts, the adapters' drop counters in the reports); 1.0.0.12 the follow-ups from 1.0.0.11's first session (the bitrate's fresh start once the GPU clock is held, the GPU clock remembered, the add-on warning limited to add-ons from outside SteamVR) and the tidier top level; 1.0.0.11 a lighter picture on the headset PC, so the Beyond's full panel resolution (now called *Native*) fits lighter headset PCs (the frame pass with about a third less work per pixel and one shader for every GPU, the pixels the lenses never show skipped, each eye shown a step smaller rather than at half the frame rate when the graphics fall behind, the pass's GPU time measured); 1.0.0.10 the follow-ups from the 1.0.0.9 test (the menu button as one clean press, Game Mode's display handover made to explain itself, the bitrate's check for uneven arrival on Wi-Fi, three tries for base stations); 1.0.0.9 clean game audio from the 1.0.0.8 test (a player of its own on the headset PC, the host's capture read straight from Windows) and lost packets rebuilt on the way; 1.0.0.8 steadier streams from the 1.0.0.7 test (the bitrate held to what the picture needs and followed during the session, pacing below the loss-free rate, the Bazzite headset PC balanced during sessions, base stations on at Start and off at closing, the gaze centred per calibration, recommended settings in one step); 1.0.0.7 a Windows client (the same client, page and stream on Windows 10 and 11, with a tray icon, sign-in start, firewall rules, Wi-Fi and power handled for sessions, Baballonia's Windows installer and a per-user installer), the frame shader's uniform-buffer variant for GPUs with less push-constant space, and one version for every package; 1.0.0.6 the follow-ups from the 1.0.0.5 test (how far the gaze reached, measured and shown with calibration guidance; the 10-bit conversion tried as plain SDR first; a network test that tells the host's sending time from the network's; the controllers' prediction measured); 1.0.0.5 the fixes from the 1.0.0.4 test (exact 10-bit colour checked by the host, eye cameras passed on as sent at their fastest rate, a quicker Baballonia filter, a comfort zone that keeps the sharp region still, *Headset not tracked*, Ultra shown at SteamVR's size, a network test that measures the network and is repeated when it finds no clean rate); 1.0.0.4 the fixes from the 1.0.0.3 test (the sharp region held where the eyes last looked through pauses in the gaze, a processor held back by the power limit noticed with a one-step GPU clock fix, wired pacing kept to the rate the network path carried without loss, no grey flashes for short stalls, Game Mode's D-pad and stick, the whole session in reports); 1.0.0.3 the fixes from the 1.0.0.2 test (Game Mode's reservation check, the host's SteamVR ownership, the reduced area filtered and smoothed, eye tracking up to 66 samples a second with a clearer view, Baballonia kept across updates); 1.0.0.2 Baballonia's calibration overlay working on Bazzite; 1.0.0.1 one name throughout and the full meaning under the name; 1.0.0 the logo, calibration over the stream, one page tab and the public-release clean-up; RC4.5 eye tracking set up and run by VROSTBridge; RC4.4 the held-back GPU advice, SteamVR crash recovery and sharper headset cards; RC4.3 the one-step host microphone, Game Mode with every setting and the one-pass frame step; RC4.2 steady poses, frame re-aim and the Wi-Fi access-point lock; RC4.1 one-step prediction and stream recovery; RC4 foveated encoding, 10-bit colour, AV1, the network test, pacing, keep-awake, Wake-on-LAN and quick resume. Earlier reviews and evidence are kept for history, not as current instructions.
