# Source overview

For VROSTBridge 1.0.0.14, host, Bazzite client and Windows client, 2026-10-18. The friendly introduction is the [README](../README.md); this page is for people reading or changing the code.

## Layout

All three programs share one source tree.

| Folder | What is in it |
| --- | --- |
| `client/` | The native client, one source for Bazzite and Windows: decoding (FFmpeg with VA-API on Bazzite, D3D11VA on Windows), Vulkan presentation, the foveated-encoding inverse, frame re-aim, tracking and input through the local SteamVR, the in-headset cards (`client/ui/`), and the Rust adapter to ALVR's client core (`client/transport/`, built as `libvrostbridge_transport.so` and `vrostbridge_transport.dll`). `client/platform/linux/` holds the main loop, Vulkan, the decoder (with `vaapi_profiles.hpp`, what the GPU decodes), the shaders and the runtime probe, which build both clients (with Windows sections), and the Bazzite-only lease helper and Vulkan layer for Baballonia's calibration overlay (`openvr_texture_layer.c`). `client/platform/windows/` holds the Windows-only parts: D3D11VA decoding on SteamVR's GPU (`d3d11_video.*`), the copy of each decoded picture into Vulkan (`vulkan_upload.cpp`), the command pipe and console events (`process.hpp`), DLL loading, and the version resource and manifest. `client/device/` holds the platform-neutral logic: the frame pass's per-frame constants and shown size (`conversion.hpp`), which pixels the lenses show (`visible_area.hpp`), the plane upload D3D11VA and CPU decoding share (`planar_upload.hpp`, `decoded_planes.hpp`), the gaze input (`gaze.hpp`) and its prediction through the head's turn (`gaze_prediction.hpp`), the controllers' acceleration folded into the poses sent (`acceleration.hpp`), and the prediction check (`prediction_check.hpp`). Its runtime assets are in `client/assets/` (the SteamVR action manifest and bindings, the cards' logo). `client/main.cpp`, `renderer.*`, `runtime.*`, `common.hpp` and `gaze_probe.hpp` are the sources of an early Windows diagnostic that is no longer built |
| `core/` | Small shared C++ contracts (versions, headset EDID rules) |
| `host/` | Windows orchestration and helpers: driver registration, the VR and audio probes, headset microphone set-up, the vendored `websockets` |
| `launcher/` | The companions (Python), shared by the rendering PC and both headset PCs: the desktop pages (`desktop.html`), the Game Mode screen (`game_ui.py`), sessions (`app.py`, `client_runtime.py`), the network test and the stream's bitrate (`network_test.py`, `stream_budget.py`), Wi-Fi and the network (`wifi_*.py`, `network_settings.py`, `adapter_counters.py`), the shown size (`output_scale.py`), the Bazzite performance balance (`session_tuning.py`), base stations (`base_stations.py`, `BaseStations.ps1`), eye tracking (`eye_tracking.py`, `baballonia.py`, `gaze_provider.py`), the host's last session (`last_session.py`), fonts and the runtime artwork (`launcher/brand/`). The Windows parts: `windows_network.py` (IP Helper and Native Wifi), `windows_power.py`, `Client-Firewall.ps1`, the tray (`windows_tray.py`) and sign-in start (`windows_startup.py`), with Windows branches in the shared modules |
| `brand/` | The VROSTBridge name and logo as the maintainer supplied them, the vectors rebuilt from them, exports, the small-icon refinement and its notes |
| `patches/` | The twenty-three ordered patches to the pinned ALVR revision: consent, networking, controllers, capture and AMF, the native protocol, chaperone, frame timing, stream statistics, pacing, foveated encoding and its gaze handling, exact colour, packet repair, and the game-audio player and capture. `scripts/host_module_tests.py` runs the tests of the driver's own Rust modules on Linux; the patched crates' own tests run with Cargo ([BUILDING.md](BUILDING.md)) |
| `third_party/` | OpenVR headers and loaders (`libopenvr_api.so`, `openvr_api.dll`), the FFmpeg n6.1.4 source used for both clients with the build notes of each (`BUILD.txt`, `BUILD-Windows.txt`), go-bsb-cams (the eye-camera helper, GPL-2.0, with VROSTBridge's changes), stb, Wayland provenance |
| `packaging/` | Installer assembly: the host's NSIS script and the launcher for both Windows programs (`windows-launcher.c`, `build_windows_launcher.py`), the Bazzite installer, `build_distributions.py`, `repack_host_payload.py`, and the Windows client's installer (`windows-client-installer.nsi`) and package builder (`build_windows_client.py`) |
| `scripts/` | The scripts that build or start each part from the source (`Build-Client-Linux.sh`, `Build-Eye-Camera-Linux.sh`, `Build-Host-Windows.cmd`, `Build-Windows.cmd`, `Start-Client.sh`, `Start-Host.cmd`, and two desktop shortcuts), the CMake toolchain for cross-building (`cross/windows-clang-cl.cmake`), builds (Linux client, FFmpeg, the Windows host's cross-build and the Windows client's: `Build-FFmpeg-Windows.sh`, `Build-Client-Transport-Windows.py`, `Build-Client-Windows.py`), the source archives (the whole source, and split by part: `package_component_sources.py`), fonts and artwork, the two PDFs |
| `tests/` | Python, page and native regression tests. Each release has a `test_vrostbridge_10NN.py` for its own changes; the Windows client's Python parts are tested on Linux with stand-ins for Windows (`test_windows_*.py`); `test_public_release.py` checks the documentation's links, the licence page and the source split. The C++ contract tests (`*_tests.cpp`) run with the client builds, the Windows ones under Wine: among them the frame pass against its CPU model, the client's own frame path against a stand-in SteamVR (`video_pass_tests.cpp`, with `openvr_stand_in.hpp` written by `make_openvr_stand_in.py`), the lens area, the plane upload, CPU decoding (with small files in `tests/fixtures/`), the gaze receiver, the acceleration and the gaze prediction |
| `licenses/` | Third-party licence texts, including every Rust crate's (`licenses/rust/INDEX.json`) |
| `docs/` | The documentation ([its home](README.md)) and the source's start page (`START_HERE.html`): guides, the technical reference and specification (each also as a PDF), the current release notes, build records in `evidence/`, the screenshot in `images/`, and the project's earlier records in `history/` |
| `.github/` | The checks workflow, the issue forms and the pull request template, with `CONTRIBUTING.md` (how to help) and `SECURITY.md` (how to report a vulnerability privately) |

`scripts/fetch_upstream.py` obtains the exact ALVR revision (`f5023f8e78fa14ea57fb1038548d7820289a8524`); the upstream checkout is not part of this repository, so native builds need internet access and the platform toolchains ([BUILDING.md](BUILDING.md)). Release packages are assembled as in [packaging/README.md](../packaging/README.md). `Build-Windows.cmd` builds and runs the contract tests on Windows with Visual Studio's CMake. The early Windows diagnostic (`VROSTBridge.exe`) is no longer built: its CMake target is gone, though its sources remain in `client/` and `scripts/package_windows_diagnostic.py` still refers to it. It was never the rendering host or the Windows headset client.

## Where things stand

- **Seen working on hardware** (one reference setup, Bazzite in Desktop Mode as the headset PC, mostly wired): Index and Beyond 2e streaming and tracking, the Beyond's eye cameras with Baballonia's calibration over the stream and the eye-tracked foveated stream, the Beyond's full size at about 75 fps, clean game audio, packet repair, the bitrate governor and the remembered GPU clock, the menu button, and in 1.0.0.14's session the video kept on the cable and the hands' worst prediction miss cut by about 40 %.
- **Built and tested in code, waiting for headset time:** the rest of 1.0.0.14 (the larger render size's effect on the picture, the gaze prediction, a Public network on the rendering PC), an Index above 90 Hz, Game Mode (which doesn't start sessions yet), and the Windows client, which has run only under Wine. [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) has the area-by-area picture, and each release's notes end with what to test.
- **Not supplied:** decoding on the Windows client without the copy through system memory, eye tracking for games through OpenXR on the host, foveated rendering in games.

Newer clients work with older hosts and turn on newer features only when a host advertises them. Version labels are independent of the protocol (`vrostbridge-session-2`); every package of a release carries the same version and is meant to be installed together.

## Release history

Each release has notes, with what changed and how to test it: the current one in `docs/RELEASE_1.0.0.14.md`, earlier ones in `docs/history/RELEASE_*.md`. In short: 1.0.0.14 what the first external testers and 1.0.0.13's first session asked for (the hands predicted with their acceleration, the host rendering larger than it streams, HEVC as the automatic codec, a higher bitrate ceiling, a Bazzite headset PC on its network twice kept on the cable, any Windows network type for paired headset PCs, the sharp region predicted through the head's turn, the host's last session kept); 1.0.0.13 the follow-ups from 1.0.0.12's first session (the stream chosen before a session from the headset's modes, more parity on a wired link, a quick stop while SteamVR starts, the adapters' drop counters in the reports); 1.0.0.12 the follow-ups from 1.0.0.11's first session (the bitrate's fresh start once the GPU clock is held, the GPU clock remembered, the add-on warning limited to add-ons from outside SteamVR) and the tidier top level; 1.0.0.11, the first public release, a lighter picture on the headset PC, so a headset's full resolution fits lighter headset PCs. The releases before it, from the release candidates to 1.0.0.10 (eye tracking, the Windows client, game audio, packet repair and the rest), are summarised in [history/CHANGELOG_EARLIER.md](history/CHANGELOG_EARLIER.md), with their notes in [`history/`](history/). Earlier reviews and evidence are kept for history, not as current instructions.
